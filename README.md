# vpnsplit

Кроссплатформенная CLI-утилита с интерактивным меню: часть трафика идёт через **корпоративный VPN**, весь остальной — через **домашний**.

Работает на Windows, Linux и macOS (amd64 и arm64), поставляется одним бинарником без зависимостей.

## Как это работает

Утилита управляет только таблицей маршрутов:

- сети и домены из ваших правил → адаптер корпоративного VPN;
- всё остальное → адаптер домашнего VPN (два маршрута `/1`, которые перекрывают маршрут по умолчанию, не меняя его).

DNS, настройки VPN-клиентов и системный маршрут по умолчанию **не изменяются**.

### Сброс к исходным настройкам

Перед добавлением маршрутов утилита записывает их в журнал (`state.json`). Команда `vpnsplit reset` удаляет ровно эти маршруты, и интернет возвращается к тому, что настроили ОС и VPN-клиенты. Это работает и после сбоя посередине применения, и без конфига. Если что-то пошло не так, просто выполните:

```
vpnsplit reset
```

## Установка

Скачайте архив под свою систему со страницы [Releases](../../releases), распакуйте и положите `vpnsplit` в `PATH`. Или соберите сами (нужен Go, версия указана в `go.mod`):

```
go install github.com/UniQlow17/vpnsplit/cmd/vpnsplit@latest
```

## Использование

Для `apply`, `reset`, `watch` и пунктов меню «Применить» / «Сбросить» нужны права: терминал от администратора (Windows) или `sudo` (Linux, macOS).

```
vpnsplit                  # интерактивное меню
vpnsplit list             # адаптеры и найденные VPN
vpnsplit init             # выбрать корпоративный и домашний адаптеры
vpnsplit add 10.0.0.0/8 intranet.company.com
vpnsplit apply            # применить маршруты
vpnsplit status
vpnsplit watch            # применять и снимать маршруты при подключении и отключении VPN
vpnsplit reset            # вернуть как было (--purge удалит и конфиг)
```

Дополнительно: `vpnsplit set corp-dns <ip>` (резолвить корпоративные домены через корпоративный DNS), `set corp-gateway <ip>` (если у VPN есть настоящий шлюз), `set home-default false` (не трогать остальной трафик).

## Ограничения

- Только IPv4.
- Оба VPN-клиента должны создавать виртуальный сетевой адаптер (TUN) (виртуальный адаптер). Клиенты, работающие как системный прокси, маршрутами не разделить.
- Домены превращаются в IP в момент применения; для обновления выполните `apply` ещё раз.
- Если корпоративный клиент сам перебивает маршруты при переподключении, используйте `watch` или авто-режим в меню.

## Разработка

```
make build      # локальная сборка
make test
make snapshot   # сборка всех платформ как в релизе (нужен goreleaser)
```

Структура:

```
cmd/vpnsplit/       точка входа
internal/cli/       команды
internal/tui/       интерактивное меню (Bubble Tea)
internal/router/    добавление и удаление маршрутов, журнал (по файлу на ОС)
internal/netif/     список адаптеров и определение VPN
internal/config/    конфиг, журнал маршрутов, правила
```

## Релиз

Релизы собираются автоматически при пуше тега:

```
git tag v0.1.0
git push origin v0.1.0
```

GitHub Actions соберёт бинарники для Windows, Linux и macOS (amd64/arm64), приложит `checksums.txt` и опубликует релиз.
