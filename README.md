# vpnsplit

Кроссплатформенная CLI-утилита с интерактивным меню: часть трафика идёт через **корпоративный VPN**, выбранные сайты — **напрямую** мимо любых VPN, весь остальной — через **домашний**.

Работает на Windows, Linux и macOS (amd64 и arm64), поставляется одним бинарником без зависимостей.

## Как это работает

Утилита управляет таблицей маршрутов:

- корпоративные сети и домены → адаптер корпоративного VPN;
- правила «напрямую» (`add --direct`) → Wi-Fi/Ethernet мимо всех VPN. Это нужно, например, для сервисов, которые не пускают с иностранных IP;
- всё остальное → адаптер домашнего VPN (два маршрута `/1`, которые перекрывают маршрут по умолчанию, не меняя его).

### VPN определяются сами

Адаптеры показываются по имени клиента: `Check Point (utun4)`, `Happ (utun225)`, `BlancVPN (utun5)`. Утилита узнаёт Check Point, Cisco, FortiClient, GlobalProtect, Happ, BlancVPN, Incy, Hiddify, Amnezia, Outline, WireGuard, sing-box, Clash и другие:

| ОС | Как определяется клиент |
|---|---|
| macOS | системные VPN-сервисы (Network Extension) и процесс, который держит `utun` (`lsof`) |
| Windows | описание адаптера (`Check Point Virtual Network Adapter…`) |
| Linux | активные VPN-подключения NetworkManager и процесс, который держит `/dev/net/tun` |

Если точно определить не удалось (без прав администратора не видно чужие процессы), туннель сопоставляется с запущенными VPN-клиентами: адреса вида `169.254.x`/`198.18.x` относятся к прокси-клиентам (Happ, sing-box…), остальные — к корпоративным.

По умолчанию оба VPN выбраны как `auto`: подходит любой подключённый корпоративный и любой домашний VPN. Поэтому можно переключаться между Happ и BlancVPN без перенастройки. Если VPN выбран вручную, сохраняется название клиента, а не номер `utunN`, который меняется при каждом переподключении.

### DNS

Если домашний VPN подменяет системный DNS (так делает BlancVPN), корпоративные домены перестают резолвиться. Утилита сама находит корпоративные DNS-серверы и их зоны и направляет эти зоны в корпоративный DNS:

| ОС | Где берутся корп. DNS и зоны | Как направляются |
|---|---|---|
| macOS | DNS, который клиент зарегистрировал в системе (`scutil`) | файлы `/etc/resolver/<зона>` |
| Windows | DNS и DNS-суффиксы корпоративного адаптера | правила NRPT с комментарием `vpnsplit` |
| Linux | `resolvectl` корпоративного адаптера или `/etc/resolv.conf` | домены маршрутизации `~зона` в systemd-resolved |

Всё это записывается в журнал и удаляется при `reset`. Чужие файлы и правила не трогаются. Отключается командой `set split-dns false`.

Настройки VPN-клиентов, системный маршрут по умолчанию и маршруты, которые поставили сами VPN-клиенты, **не изменяются**.

### Сброс к исходным настройкам

Перед добавлением маршрута или DNS-файла утилита записывает его в журнал (`state.json`). Если маршрут уже существует (его поставил VPN-клиент), он в журнал не попадает. Команда `vpnsplit reset` удаляет ровно то, что добавила утилита, и интернет возвращается к тому, что настроили ОС и VPN-клиенты. Это работает и после сбоя посередине применения, и без конфига. Если что-то пошло не так, просто выполните:

```
vpnsplit reset
```

### Жизненный цикл

Меню и `vpnsplit run` работают как **сеанс**: при запуске (с правами) утилита доделывает то, что мог оставить прервавшийся прошлый сеанс, и применяет правила; при выходе любым способом (`q`, Ctrl+C, закрытие окна консоли, SIGTERM/SIGHUP, паника) снимает всё, что применила: сначала DNS, потом маршруты, и пишет, что снято. Время на снятие зависит от причины выхода:

- обычный выход (`q`, пункт «Выход», клавиша Ctrl+C в меню, SIGINT у `run` в терминале): до 60 секунд, с выводом прогресса;
- закрытие окна консоли, выход из системы, выключение (SIGTERM/SIGHUP): около 4,5 секунд, считая от момента сигнала (Windows даёт процессу около 5 секунд; в них входят и 0,5 с на закрытие меню, и восстановление терминала).

Если не успела или не смогла, остаток остаётся в журнале, об этом сообщается и выход идёт с ненулевым кодом; следующий запуск (или `vpnsplit reset`) доделает. Второй сигнал (второй Ctrl+C) во время снятия обрывает его: выход сразу, журнал остаётся, следующий запуск доделает. После `kill -9` или выключения питания работает то же правило: журнал записывает владельца (PID, время старта процесса, номер загрузки), мёртвого владельца видно по блокировке `vpnsplit.lock` рядом с журналом: пока блокировка свободна, прежний владелец не работает, даже если PID жив (он мог достаться другому процессу; это только предупреждение). После перезагрузки маршруты из журнала считаются исчезнувшими вместе с ней и просто забываются (чужой маршрут к тому же адресу не трогается), а DNS-записи снимаются. Если журнал ошибся (скачок часов), `vpnsplit reset --force` пробует снять все записанные маршруты.

Когда сеанс снял полный туннель домашнего VPN (`0.0.0.0/1` + `128.0.0.0/1`), он пишет: весь трафик теперь идёт напрямую через провайдера (мимо домашнего VPN), пока VPN-клиент сам не направит его в туннель. Итог каждого сеанса записывается в `last-session.log` рядом с журналом (окно закрытой консоли никто не видит): его показывают `vpnsplit status` и меню при следующем запуске. Если сеанс умер, не сняв DNS-правила (NRPT на Windows), `status` и меню предупреждают об этом: запустите vpnsplit с правами администратора, и они будут сняты.

`vpnsplit apply` и `vpnsplit watch` ничего сами не снимают (режим `persistent`): маршруты остаются до `reset`. `vpnsplit run` поверх таких маршрутов забирает их себе (он явно сеанс), и при выходе они будут сняты. Меню так молча не делает: если при запуске меню в журнале есть маршруты от `apply`/`watch`, оно показывает заметное уведомление «Маршруты применены командой apply/watch (постоянные). [t] Забрать в сессию — будут сняты при выходе» и не включает авто-режим. Пока вы не нажали `t`, при выходе из меню ничего не снимается (применить заново или сбросить из меню можно: это то же, что команды `apply` / `reset`; после сброса меню снова обычный сеанс). Если журнал пуст или остался от умершего сеанса, меню ведёт себя как раньше: доделывает прошлое и снимает своё при выходе. Одновременно управлять сетью может только одна копия: вторая показывает состояние и ничего не меняет. Без прав администратора меню тоже только показывает состояние и подсказывает, как запустить его с правами.

## Установка

Скачайте архив под свою систему со страницы [Releases](../../releases), распакуйте и положите `vpnsplit` в `PATH`. Или соберите сами (нужен Go, версия указана в `go.mod`):

```
go install github.com/UniQlow17/vpnsplit/cmd/vpnsplit@latest
```

## Использование

Для `apply`, `reset`, `watch` и пунктов меню «Применить» / «Сбросить» нужны права: терминал от администратора (Windows) или `sudo` (Linux, macOS).

```
sudo vpnsplit             # интерактивное меню, авто-режим включится сам
vpnsplit list             # адаптеры и VPN-клиенты за ними
vpnsplit init             # закрепить конкретные VPN (по умолчанию auto)
vpnsplit add 10.0.0.0/8 intranet.company.com     # через корпоративный VPN
vpnsplit add --direct telework.bank.ru           # напрямую, мимо VPN
vpnsplit export rules.txt                        # сохранить правила в файл
vpnsplit import rules.txt                        # добавить правила из файла
vpnsplit apply            # применить маршруты
vpnsplit status
vpnsplit watch            # следить: VPN подключился, сменился, отключился, правила изменились
vpnsplit run              # то же, но сеансом: при завершении всё снимается (для скриптов, служб)
vpnsplit reset            # вернуть как было (--purge удалит config.json, --force снимет и то, что считалось исчезнувшим после перезагрузки)
```

Дополнительно: `vpnsplit set corp|home <auto|клиент|адаптер>`, `set corp-dns <ip>` (если не определился сам), `set corp-gateway <ip>` (если у VPN есть настоящий шлюз), `set home-default false` (не трогать остальной трафик), `set split-dns false` (не трогать DNS).

### Номер AS вместо сетей

Вместо списка сетей организации можно указать номер её автономной системы: `vpnsplit add --direct AS49675`. При применении утилита берёт из [RIPEstat](https://stat.ripe.net) все IPv4-сети, которые объявляет эта AS, и склеивает их в минимальный набор. Ответ кешируется на сутки (`ripe-cache.json` рядом с конфигом). Если RIPE недоступен, используется последний сохранённый список. Номер AS организации по IP-адресу показывает `whois <ip>` (строка `origin`).

### Файл правил

Правилами можно делиться: «Экспорт» (`vpnsplit export <файл>`) сохраняет их в текстовый файл, а «Импорт» (`vpnsplit import <файл>`, или «Правила» → «Импорт из файла…» в меню) добавляет правила из файла к своим.

```
# комментарий
[direct]            # дальше — напрямую, мимо VPN
217.12.96.0/21
AS49675             # все сети автономной системы, по данным RIPE
[corp]              # дальше — через корпоративный VPN
intranet.example.com
```

Правила до первого раздела идут в корпоративный VPN, как у `vpnsplit add`. Строки с ошибками пропускаются, о них выводится сообщение.

## Ограничения

- Только IPv4.
- Оба VPN-клиента должны создавать виртуальный сетевой адаптер (TUN) (виртуальный адаптер). Клиенты, работающие как системный прокси, маршрутами не разделить.
- Домены превращаются в IP в момент применения; для обновления выполните `apply` ещё раз.
- Если корпоративный клиент сам перебивает маршруты при переподключении, используйте `watch` или авто-режим в меню.
- «Напрямую» использует шлюз Wi-Fi/Ethernet. Если домашний VPN принудительно заворачивает весь трафик (kill switch, «include all networks»), прямые маршруты он может заблокировать.

## Разработка

```
make build      # локальная сборка
make test
make snapshot   # сборка всех платформ как в релизе (нужен goreleaser)
```

Windows без make (PowerShell, нужен только Go):

```
.\build.ps1                      # сборка vpnsplit.exe
.\build.ps1 test                 # тесты (также: vet, fmt)
.\build.ps1 build -Version 1.2.0 # сборка с указанной версией
.\build.ps1 clean                # удалить артефакты сборки
```

Цель snapshot через build.ps1 не поддерживается: используйте `goreleaser release --snapshot --clean`.

Если запуск скриптов заблокирован политикой выполнения:
`powershell -ExecutionPolicy Bypass -File .\build.ps1`.

Структура:

```
cmd/vpnsplit/       точка входа
internal/cli/       команды
internal/tui/       интерактивное меню (Bubble Tea)
internal/router/    маршруты, шлюз, split DNS, журнал (по файлу на ОС)
internal/netif/     список адаптеров, определение VPN-клиентов (owners_*.go по ОС)
internal/config/    конфиг, журнал маршрутов (владелец, блокировка), правила
internal/sysproc/   PID, время старта процесса, номер загрузки ОС
internal/lifecycle/ сигналы завершения, безопасные горутины
test/stand/         сетевой стенд в Docker (см. test/stand/README.md)
```
